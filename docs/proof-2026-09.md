# pollen — proof runs, September 2026

## Cross-harness: Codex CLI ↔ Claude Code

The README claims pollen works with any MCP-compatible agent and names Codex CLI and
Gemini CLI. That claim was inherited from walkie-clawkie and had never been tested. It
is now tested for Codex, in both directions, with the receiving journal as ground truth
rather than an agent's report of success.

**Versions:** `codex-cli 0.133.0`, Node v26.4.0, pollen v0.1.0.

### The configuration that worked

```bash
codex mcp add pollen \
  --env POLLEN_ID=codex \
  --env POLLEN_DIR=/tmp/pollen-crossharness \
  --env POLLEN_ALLOW=yokohama \
  -- node /path/to/pollen.mjs
```

Codex registers stdio MCP servers globally and passes `--env` through to the child, which
is all pollen needs. No wrapper, no shim, no adapter: the same file Claude Code spawns.

### Codex → Claude Code

Codex was asked to call `pollen_send` to the peer `yokohama`. The receiving peer's
journal, written by pollen itself:

```json
{"seq":1,"ts":"2026-09-05T13:36:48.390Z","from":"codex","message":"ping from codex — cross-harness check","status":"delivered"}
```

The peer's polling loop printed:

```
RECEIVED: [codex]: ping from codex — cross-harness check
```

### Claude Code → Codex

Sent while Codex's MCP server was **not** running, which exercises the honest-status
path rather than the happy one. `pollen_send` returned:

```
Queued for codex — no confirmation from codex's pollen; it stays in the mailbox until taken.
```

That is the correct answer — the message was on disk but nothing had taken it — and it is
the distinction the sender would otherwise have had to guess at. The mailbox file sat
waiting:

```
/tmp/pollen-crossharness/codex/inbox/1788615431776_dkv5_from_yokohama.msg
```

Codex was then started and asked to call `pollen_inbox`. It replied with exactly:

```
[yokohama]: pong from yokohama — the gate is open both ways
```

and its own journal recorded the arrival on startup drain:

```json
{"seq":1,"ts":"2026-09-05T13:37:21.192Z","from":"yokohama","message":"pong from yokohama — the gate is open both ways","status":"delivered"}
```

### What this proves, and what it does not

Proven: a non-Claude host runs pollen unmodified, sends and receives, and the durability
path works across the gap — a message sent to an agent that is not running is held on
disk and delivered when it starts, with the sender told which of those happened.

Not proven: **Gemini CLI**. It is installed (0.46.0) but was not tested. The README names
it; treat that as untested until someone runs the same exchange.

Also not exercised here: the relay. Both peers were on one machine, so this is the file
transport only.
